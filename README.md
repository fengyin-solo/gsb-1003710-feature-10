# 水文监测站网管理系统

面向水文监测站点运行、水位流量雨量数据采集、遥测设备维护与数据整编发布的水文站网管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydrology-monitor-station:entries` 这一项，或调用 `resetModule(模块)`。

## 预警阈值生命周期

预警阈值配置带**生效窗口**（生效起始/截止），状态机只许前进、任何阶段都不能跳回草稿：

```text
草稿 --提交校验(校验通过)--> 待复核 --复核排期--> 已排期 --触发生效(到点)--> 已生效 --归档配置--> 已归档
```

- 流转逻辑集中在 `frontend/src/api/threshold-service.ts`，通用 `runAction` 不再直接改预警阈值的状态。
- **校验**：四级阈值必须是数字且蓝<黄<橙<红逐级递增，生效起始早于截止；校验不过不能提交复核。
- **权限**：复核排期/触发生效需要「复核员」及以上，归档配置需要「系统管理员」，越权操作直接拒绝；
  当前角色在页面右上角切换（会话存于 `stores/session.ts`）。
- **版本切换**：同一站点同一监测类型允许窗口重叠，生效起始较晚的版本优先；新版本生效时，
  窗口重叠的已生效旧版本自动归档。水位记录登记时快照当时适用的阈值版本（适用配置/适用阈值），
  历史水位因此继续引用当时的门槛。
- **并发**：同一站点+监测类型+生效窗口的在途配置（待复核/已排期/已生效）只留一份，
  重复提交被合并拒绝；写操作前会重读 localStorage，多标签页并发提交也只留先落库的一份。
- **失败保留旧版本**：所有流转先校验再整体落库，任何一步失败都不写入，旧版本配置原样保留。
- **复核记录**：复核排期会写一条复核记录（`warning-review`），水位监测页面同步展示水位类复核记录。
- **旧配置迁移**：旧格式数据（无生效窗口、状态为已调整/已停用）在读取时自动迁移——
  状态映射到新状态机、补默认窗口与版本号、阈值非法的降级为草稿待修正，迁移幂等。
